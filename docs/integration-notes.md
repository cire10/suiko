- WP3: `commitVersion(docOrId, {source, ext?, manifest?, assetFiles?})` - pass the Doc object you hold (its `head` is set and it is saved), else doc.json is re-read. ## WP6 -> WP7: guest protocol details as implemented (MSG in protocol.js)
- Handshake: on DOMContentLoaded the guest posts `hello {target, title, href, highlightApi, guestVersion}` to the parent origin (from `location.ancestorOrigins` when available, else to every `data-sr-ui` origin). Install the UI's window `message` listener BEFORE setting the iframe `src`. On the first `hello` from `iframe.contentWindow` + content origin, create a `MessageChannel` and post `{sr:1,type:'connect'}` with `port2`. The guest accepts exactly ONE connect per page load and then ignores every window message (a second connect is ignored): re-handshake only by reloading the iframe (a reload sends a new `hello`).
- `ready {outline, features, externalsFailed}` is sent right after connect, independent of `init`; `init` may be sent at any time after connect (messages that arrive before the guest finished starting are queued).
- Coordinates: `selection.rect` / `action.rect` are DOMRect JSON `{x,y,width,height,top,left,right,bottom}` in the IFRAME VIEWPORT (add the iframe's client rect). `positions.targets[id] = {top, height, state}` uses IFRAME DOCUMENT coordinates (viewport = top - positions.scrollY). `hidden` targets report the nearest visible ancestor's top; `missing` -> `top: null`; DomTarget `kind:'doc'` -> `{top: 0, height: 0, state: 'ok'}`. `positions.hunks[id]` = document top, or `null` while hidden. Positions are posted only when they change; scroll-only changes are throttled to 100 ms.
- `scroll {topSrid, offset}` when scrolling settles (offset = viewport top of that element); restore with `scrollTo {srid, offset}` (`offset` is an additive, optional field). `scrollTo {hunk}` / `{id}` also reveal hidden content first.
- Pick mode: every completed pick posts `action {action:'comment', capture, rect, crop?}`, then exits pick mode and posts `toolChanged {tool:'select'}` (also on Esc); send `setTool {tool:'pick'}` again to pick another target. The table-cell chooser (Cell / Row / Column / Table, keys 1-4, Enter = cell) lives in the guest.
- Key forwarding (`key {key, meta, ctrl, shift, alt}`): only single printable characters without Cmd/Ctrl/Alt, `Escape`, and `Enter` with Cmd/Ctrl; never from editable focus, never when the page called preventDefault, never `[` `]` Esc 1-4 while picking (consumed). Esc first closes an open "removed" popover (not forwarded). Keys pressed while focus is in the UI never reach the guest, so the UI handles `e`/Esc itself and sends `setTool`.
- `init`/`setTargets` accept `targets` plus optional `locks` / `drafts` arrays (merged; ids must be unique across them). Colours by DomTarget.state: open/addressed/needs_input -> `sr-open`, resolved -> `sr-resolved` (only while active; otherwise no highlight, pin, outline or click target, but its position is still posted), outdated/orphaned -> `sr-outdated`, draft -> `sr-draft`, lock -> `sr-lock` + left bracket (no pin). `kind:'section'` gets a bracket and a pin. `focus {id: null}` clears the active highlight. Pins show `num` (or a dot when null).
- Clicking a pin, a highlighted range, an outlined element target, a lock bracket or a change badge posts `activate {id}` (and marks it active locally). Forwarded/guest messages never mutate state (amendments 7).
- `mode:'readonly'` disables the selection toolbar, selection captures and pick mode. `setHidden {hidden:true}` hides highlights, pins, outlines and change marks (the selection toolbar still works).
- Additive fields: `hello.guestVersion`, `pageError.externalsFailed`, `pageError.resourcesFailed` (same-origin failures), `scroll.offset`.
- e2e debugging: the overlay is a closed shadow root; use `frame.evaluate(() => __specreviewGuest.inspect())` (non-enumerable global in the doc iframe) to read pins / outlines / toolbar / chooser button rects.
- **Integration: informational, no action.** The UI follows it (handshake verified against the real daemon). One guest change: the "⊖ was" tab and the badge row of a changed element now go after the end of its first line when there is no free margin above the element (they used to cover the previous line of a list).

## WP6 -> WP3: capture conventions as implemented (shapes are the frozen ones of amendments 3.3)
- text: `exact` = rendered text of the range (TEXT_EXCLUDE applied, so math MathML / mermaid source / scripts are skipped), whitespace kept verbatim except trimmed at both ends; a single `\n` is inserted where two blocks (or a `<br>`) meet without whitespace (`<p>a</p><p>b</p>` -> `"a\nb"`). `prefix`/`suffix`: up to 32 chars, whitespace runs collapsed to one space, the side touching the quote keeps its space. `startSrid`/`endSrid` may be `null` when no stamped ancestor exists.
- element: `srid`/`tag` = the nearest stamped element (inclusive) of the visual target; `label` names the visual target (e.g. `{srid: <pre srid>, tag: 'pre', label: 'mermaid node "Gateway"', svg: {...}}`, `img "System overview" region x10-50% y20-70%`). Selections whose ends are both inside one math element (`.sr-math` / `[data-sr-kind=math]` / `.katex`) or one mermaid diagram snap to an element capture of it.
- region `{x,y,w,h}`: fractions (4 decimals) of the border box (getBoundingClientRect) of the stamped element the capture names (Capture.regionBox). One rule for pick shift-drag regions, snips (`b`, whose containerSrid can be any element) and the painter, so a region paints back where it was drawn. `action.crop` is a PNG data URL (<= 1024 px for pick regions; snips: exactly the boxed area, <= 1600 px wide), omitted when the source is tainted or not croppable.
- svg `{nodeId, label}`: nodeId from mermaid's `data-id`, else parsed from the group id (`flowchart-<id>-<n>`, `state-`, `classId-`, `entity-`), label = the node's text.
- cell `{row, col, rowKey, colHeader, text}`: 0-based indices in the rowspan/colspan-expanded grid over `table.rows` (thead rows included); rowKey = text of the row's first grid cell, colHeader = text of the header row's cell in that column (header row = last `<thead>` row, else row 0). `scope:'cell'` -> srid/tag of the td/th; `'row'` -> the `tr` (cell kept); `'column'` -> the `table` (cell kept); `'table'` -> the `table` (no cell).
- DomTarget quotes are matched whitespace-insensitively (runs collapsed, then all whitespace ignored), scoped to srid..endSrid first, then the whole document; element kinds = `kind` 'element' | 'cell' or any target with region/svg/cell.
- **Integration: informational, no action.** The engine resolves these captures (exercised end to end through POST /anchors/resolve in e2e-loop.test.js).

## WP5 -> WP4: starting and stopping the daemon (src/daemon/main.js as implemented)
- `startDaemon({ foreground, uiPort, contentPort, ops?, createContext?, home?, rotate?, idleMs?, idleCheckMs?, pingMs?, timing?, dev?, logFile? })` resolves once both servers listen and daemon.json is written, with `{ uiPort, contentPort, token, secret, version, info, uiOrigin, contentOrigin, close(reason?), closed }`. **It does not block**: `serve --foreground` must keep the process alive, i.e. `const d = await start(...); await d.closed;` and must NOT call `process.exit()` when execute() returns. In foreground mode the daemon installs SIGINT/SIGTERM handlers and exits the process itself (code 0) after a graceful shutdown (POST /api/shutdown, idle exit or a signal).
- Ports: explicit `uiPort`/`contentPort` are strict (busy -> rejects with `err.code === 'EADDRINUSE'`, message names the port); `contentPort` defaults to `uiPort + 1` when only `uiPort` is given. `SPECREVIEW_PORT=N` in the daemon's environment is treated like `uiPort: N` (so `serve --port N` in background mode works through ensureDaemon's env). Without explicit ports: previous daemon.json ports (sticky), then (4777,4778), (4779,4780)... up to 4799, then random.
- Token (32 hex) and secret (64 hex) are reused from daemon.json unless `rotate: true`; daemon.json is kept on shutdown (deleting it, as `stop --rotate` does, also rotates). `startDaemon` rejects (`err.code === 'DAEMON_RUNNING'`) when daemon.json names another live pid that answers /api/health as specreview with that pid.
- Logging: foreground -> stderr with timestamps at level info (your spawn redirects it to daemon.log); otherwise lines are appended to `logFile` (default daemon.log; `false` disables). The token/secret are never logged (query strings are stripped from request logs).
- /api/health = `{ok:true, name:'specreview', version, pid}`; POST /api/shutdown needs the Bearer token; an Origin header is optional for non-browser clients that send `Authorization: Bearer` (a present Origin must equal `http://<Host>`).
- **Integration: resolved.** `serve --foreground` awaits `closed`; `SPECREVIEW_PORT` reaches the spawned daemon; `stop` uses the Bearer token. Verified with real processes (cli-daemon-real.test.js on ports 5800-5849, e2e-loop.test.js and cli-loop.spec.mjs on 5850-5899).

## WP5 -> WP3: how the daemon calls the engine
- Loaded lazily: `import('src/core/review/ops.js')` (+ `createContext` from ops.js or context.js). While it cannot be loaded, engine routes answer 503 `{code:'ENGINE_UNAVAILABLE'}` (retried every 2 s); a missing function answers 501 `{code:'NOT_IMPLEMENTED'}`. Contexts: `createContext({ root, cwd: root, store })` once per workspace (cached 60 s).
- Calls (ctx first; `by` is the reviewer NAME string from ctx.reviewer; versions are numbers, or 'live' where the URL says live):
  `docState(ctx, docId)` (daemon adds `contentBase` and defaults `ws`), `domTargets(ctx, docId, v)` (daemon adds `outline` from getRender when absent and defaults `drafts: []`), `resolveCapture(ctx, docId, {version, capture[, widen]})`, `saveDraft(ctx, docId, item)` (POST, client `id` stripped), `updateDraft(ctx, docId, id, patch)` (PATCH; when absent the daemon merges into the stored draft and calls saveDraft with the id), `deleteDraft(ctx, docId, id)`, `submitReview(ctx, docId, {verdict, body, markFinal, resolveAddressed, draftIds?, expectHead?, by})` (the daemon passes the body's `reviewedVersion` / `expectHead`; an approval of another head is a 409 ConflictError), `resolveThread(ctx, docId, tid, {by, decision?})`, `unresolveThread(ctx, docId, tid, {by})`, `moveThread(ctx, docId, tid, {version, capture, lines, quote, by})`, `applySuggestionAsReviewer(ctx, docId, tid, {by})`, `threadMiniDiff(ctx, docId, tid)`, `addLock(ctx, docId, {version, capture, note, by})`, `removeLock(ctx, docId, lockId, {by})`, `relock(ctx, docId, lockId, {by})`, `changes(ctx, docId, {from, to})`, `sourceDiffOp(ctx, docId, {from, to})` (from/to default: to = head, from = lastReviewedVersion if < to else to-1; to may be 'live'), `recordReviewerVersion(ctx, docId, {summary, by})`, `saveAttachment(ctx, docId, {dataUrl})` (already validated: PNG/JPEG data URL, magic bytes checked, <= 5 MB; may return a string path or {path}), `closeSession(ctx, docId)`.
- Error mapping: NOT_FOUND -> 404, CONFLICT/REFUSED -> 409, USAGE (and RangeError/ZodError) -> 422, LOCK_TIMEOUT -> 503 (Retry-After 1), anything else -> 500. Body `{error, code[, details]}`. Read-only routes that need no engine (doc list, GET drafts, source lines, fragment previews, content origin) use the store/render directly.
- Events: the daemon only reads `<home>/ws/<wsId>/events/<doc>.jsonl` (tail by byte offset) and waiter files; every state change the UI should see must be appended by the ops with `store.appendEvent` (drafts.changed included).
- **Integration: resolved.** Every listed op exists with that signature; exercised through the HTTP API with the real engine in e2e-loop.test.js and the Playwright suites.

## WP5 -> WP7: API and SSE details the UI can rely on
- `GET /api/docs` entries: `{ws, root, id, path, title, format, head, state, openThreads (status != resolved), undelivered (reviews with empty deliveredTo), listening (live waiter on the doc or a wait --all), final}`, sorted by workspace root then doc id.
- `DocState.contentBase = http://127.0.0.1:<cport>/c/<docKey>`; doc URL = `${contentBase}/${ver}/${encodeURI path segments of doc.path}` with ver `live` or `v<N>` (percent-encode each segment: `#`/`?` in file names). `/c/<docKey>/<ver>` (no path) redirects to the doc.
- `GET .../source?v=&from=&to=` -> `{v, startLine, lines, total}` (v defaults to live; to is clamped). `GET .../versions/:v/targets` -> `{threads, locks, drafts, outline, ...}`. DELETE routes and close answer `{ok:true, ...opResult}`.
- SSE `/api/events?ws=&doc=&k=`: stream starts with `retry: 3000` and an `id: <lastSeq>` line (no event), then `presence {waiters, ws, doc}` and `working.changed {dirty, sha256, ws, doc}` (no id); store events carry `id: <seq>` and `data = {...record, ws, doc}`. Resume via the `Last-Event-ID` header or `?lastEventId=`; unknown/too old ids get `reset` (with `id: <lastSeq>`). `ping {at}` every 25 s. Without `doc` (optionally with `ws`): a global stream of new events of every doc (payload has ws/doc, no ids, no replay) and per-workspace `presence {ws, doc:null, waiters}`.
- The UI CSP is design 12.4 plus `media-src 'self' data: blob: <content>`, `font-src 'self' data:`, `form-action 'none'` (same as src/ui/csp.js); every inline script of index.html is allowed by hash (computed per mtime, so edits need no restart). index.html's own inline import map is kept; when absent, src/ui/importmap.json (or a default map) is inserted after <head>.
- **Integration: informational, no action.**

## WP3b -> WP4/WP5/WP7: review engine notes (as implemented)
- Delivery callback: `feedback()` / `waitForFeedback()` now call `write(text, packet)` (formatted text + the Packet object of design 9.3) under the doc lock; the review is marked delivered only after it resolves. The CLI's `buildDocPacket` rebuild for `--json` is no longer needed (still harmless). The flaky supersede test reported by WP4 was a test race (the newer wait marks the older one superseded just before writing its own waiter file); fixed in the test.
- `waitForFeedback(ctx, { docIds: [id] | '*' | null, timeoutMs, allowDirty, signal, onStart, write, pid?, pollMs?, heartbeatMs? })` -> `{ status: 'delivered'|'timeout'|'closed'|'dirty'|'superseded', packets, text, docId?, by?, aborted? }`. 'dirty' / 'closed' return at once without registering a waiter; an aborted signal returns `{status:'timeout', aborted:true}`; a `write` that throws propagates (nothing marked delivered, waiter file removed).
- `revise` / "Record as my revision": a working copy whose text equals head but whose local assets (images referenced by the doc) changed is recorded as a new version (amendments 4.5); `report.assets = [{path, threads}]` lists them and threads anchored on the image count as linked. `wait`'s dirty check and `docState.working.dirty` still compare the spec file only.
- Lock guard: a lock is intact when its whitespace-normalised source text survives OR the rendered text of its range equals the rendered text of the mapped range (re-wrapping a blockquote with `> ` continuation markup is not a violation). Its re-anchored state may then be `changed` (fuzzy), which is expected.
- Ops not in design 4.4 that surfaces may use: `listDrafts`, `taggedEdits` (edit --stdin, all or nothing), `unifiedDiff` (`diff --unified`), `threads`, `buildDocPacket`, `parseReviseInput`, `resolveAgentName`. Formatters (src/core/review/index.js or packet.js): formatPacket, formatReviseReport, formatStatus, formatLog, formatDiffStat, formatThread, formatThreads, formatApply, formatEdit, formatRevert, formatFinal, formatSourceLines, formatReply, formatAsk, verdictLabel.
- `resolveDoc` is intentionally NOT exported from ops.js, so the CLI keeps its own "doc not found (tracked: ...)" message via `store.findDoc`.
- **Integration: informational.** Small engine changes: `threads` summarises a suggestion without a comment as `suggests: <new text>` (also the decisions.md headline); a dry-run refusal prints `specreview: dry run - would be REFUSED (exit 3)`; hunk tables (revise report, `diff --stat`) print the section as `§3.2 Token refresh` as in design 3.5/9.2.

## WP3a -> WP3b/WP4/WP7: anchor library as implemented (`src/core/anchor/index.js`)
- Anchor kinds are `text | code | element | cell | section | source | doc` (types.js `AnchorKind`): a text capture fully inside a code block's verbatim content becomes `kind:'code'` with `code:{fromLine, toLine, lang?}` (1-based within the block); an element capture with `cell` becomes `kind:'cell'` with `scope` ('cell' default | 'row' | 'column' | 'table') and `cell.tableSrid`. Generated text anchors (`generated:true`, mappedBy `raw-source` | `block`) carry an extra `host:{tag, s, e, label}`; their `srid` is the host element, so the DOM target stays on the rendered text while `src` points at the script / container markup.
- `reanchor({...})` extra inputs: `version` (default anchor.v + 1), `docPath`, `assets` (manifest `assets` of version b; without it the previous asset hash is kept), `hunks` may be manifest hunks without offsets (recomputed with lineHunks, ids are deterministic). `link = {hunkIds, linked}`: `linked:true` alone (asset-only change) turns an asset change into 'edited'; it never moves an anchor. Output extras: `assetChanged:true` (image bytes changed: 'changed', or 'edited' when linked), `lastKnown` on orphans (never nested; the next version retries from it).
- Sections and locks recompute their extent every version: 'exact'/'moved' only when the whole section text is unchanged (heading found by text + level, a promoted/demoted heading is 'changed'). A row appended to a locked section therefore makes the lock 'changed' ('edited' when the hunk is linked), so the lock guard refuses as intended.
- Never silently wrong: a text that occurred several times in version a must be re-found by its context (no unique-survivor shortcut), so deleting one copy orphans its thread instead of moving it onto another copy.
- `describeAnchor` also returns `asset` (absolute via `absAssetPath`), `crops` (absolute via `absAttachmentPath`) and, for orphans, `lastKnown: {v, lines, section, text}` (for `(orphaned: was "..." in §5 v1 L260)`); `lines`/`src` are null for orphans and doc anchors. `workingMapper` is computed when omitted and the texts differ.
- `toDomTarget`: `cell` includes the anchor's `scope`; anchor state 'changed' -> display 'outdated' (except resolved / draft / lock); orphaned -> 'orphaned' with null srid/endSrid/quote; srids missing from the given render are dropped; `label` defaults to `anchorLabel(anchor)` (e.g. `table cell row "refresh_token" x col "TTL" = "30 d"`, `mermaid node "API Gateway"`, `§3 Tokens`, `script-rendered text inside <ul id="generated">`, `GENERAL`).
- **Integration: informational.** Two fixes in reanchor.js step 2 (linked & intersecting): (1) when both end characters of the range survive a linked hunk, the anchor spans the text between them (an applied suggestion used to be narrowed to a fragment cut inside inline code, e.g. ``Ship rotation behind the `token_rotation``, whose quote the guest could not find); (2) when the linked hunk is a pure deletion, steps 3-4 run first, so moved text is followed (moved / edited) instead of collapsing to the empty deletion point. Unit tests in anchor-reanchor.test.js.
